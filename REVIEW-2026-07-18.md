# Full-codebase review — 2026-07-18

Four-perspective review (architect, RF/power, code quality, QA) against the
project goals: **power-efficient, robust/self-healing, fast boot, light
maintainable codebase**. Each agent read the code and cited line evidence;
findings below are deduplicated and ranked. Known/deferred items (blocking
go-librespot API, seamless output switch, boot I/O stall, HCI page timeout)
are excluded on purpose.

Legend: effort S = under an hour, M = an afternoon, L = a day+.

---

## P1 — Robustness: can silence the box or stutter audio

- [x] **R1. Verify — then pin — wpa_supplicant background scanning off.** (S)
  Nothing in the repo manages bgscan; NM passes `bgscan="simple:30:-70"`
  (visible in every boot log). If armed, that is a full 13-channel
  off-channel sweep (~1.5–2 s radio absence) every 30 s whenever RSSI is
  below -70 — a macroscopic burst that bypasses the whole marker system and
  can explain any remaining unexplained A2DP stutter. NOTE: the logs also
  show `bgscan simple: Failed to enable signal strength monitoring`, so it
  may effectively be off on brcmfmac — **verify on the rig**
  (`wpa_cli -i wlan0 status`), then pin it off via nmcli/NM conf either way.

- [x] **R2. ORCH.lock is held across slow I/O; every reader blocks.** (M)
  `status()` (1/s screen poll) blocks behind writers that hold the lock for
  seconds: `_spot_control` does 5s-default status calls under lock
  (spotify.py:247–267), `play()` runs `_ensure_spotify_backend`
  (systemctl, up to 30s) under lock (daemon.py:512), `set_output` runs
  `systemctl restart go-librespot` under lock (output.py:113 via
  daemon.py:681–695). This re-creates the frozen-UI class that
  GO_STATUS_TIMEOUT was added to kill. Fix: readers
  (`status`, `_audible_now`, `_streaming_now`, `_bt_playback_active`) use
  `lock.acquire(timeout=0.3)` + a lock-free snapshot tuple; move the two
  systemctl calls out from under the lock (stamp intent inside, execute
  after release).

- [x] **R3. Three non-atomic writes can brick audio on a brown-out.** (S)
  `bt._route_alsa` plain-writes /etc/asound.conf (bt.py:359), `bt.connect`
  writes MAC_FILE directly (bt.py:332), `spotify._set_zeroconf`
  truncate-writes config.yml in place (spotify.py:109). Battery box +
  power cut mid-write = no PCMs / go-librespot won't start, and nothing
  heals it. Every JSON writer already does tmp+rename; these are the only
  three holes. Fix: tmp+`os.replace` (+chown for config.yml ownership).

- [x] **R4. library.json read-modify-write races lose parent edits.** (S)
  Three writers, no lock: PUT /library (daemon.py:1360), section-logo
  (daemon.py:1457), and the sweeper's profile sync (library.py:142) which
  runs right after every save. A PUT during the sweeper's stale window is
  silently reverted. Fix: module-level `LIB_LOCK` in library.py around
  load→save at all three sites.

- [x] **R5. A crashed mpv/player child has no healer.** (M)
  The stall watchdog stands down when the child is dead (daemon.py:311–316);
  an OOM/segfault mid-audiobook = silent box with "playing" on screen.
  Contrast: BT blips auto-resume. Fix: watchdog branch — child dead with
  nonzero rc + was playing recently → respawn once via `_spawn`, max 2 per
  boot, same no-surprise-audio window as BT_RESUME_S.

- [x] **R6. Recovery can be killed mid-recovery; bluezd death has no healer.** (S)
  /bt/connect kills bt.py at 90s (daemon.py:1591) but `recover()` firmware
  re-attach can exceed that — potentially between `rfkill block` and
  `unblock` (bt.py:212–215), leaving the radio down. Fix: raise the
  endpoint timeout to 240s and wrap block/unblock in try/finally. Also:
  bluetoothd dying without the firmware-crash signature has NO healer
  (btwatchd goes quiet by design) → add `Restart=on-failure` drop-in for
  bluetooth.service in install.sh.

- [x] **R7. `_BT_WAIT` written without its lock in three places.** (S)
  `_kick_bt_connect` (daemon.py:2022), `_bt_transport_lost` (1851, 1857),
  `_bt_wait_state` read (1996). Concrete race: a fresh play-intent can be
  consumed by a stale transport-up event → the "waiting…" popup never arms.
  Fix: take `_BT_WAIT_LOCK` in those writers (never held across I/O).

## P2 — Power: measured/estimated standing drains

- [x] **P1. Offline supervisor: probe + park churn around the clock.** (S)
  TCP probe to 1.1.1.1 every 20s forever (daemon.py:2071) wakes the radio
  out of its PS nap (~+10–20 mW avg, 2–4 % of idle draw); once offline it
  also forks `systemctl stop` every tick (daemon.py:2134). Fix: stretch to
  120–300s when online+idle; only stop when `_go_unit_active()`; add
  `TAPBOX_PROBE_ADDR` env (QA wants it too, Q2).

- [x] **P2. PWA polls with no visibility gating.** (S)
  app.js polls /status 2s + /system 60s while the tab is open — a docked
  parent phone keeps the box radio awake (~+30–60 mW). Fix:
  `visibilitychange` stops polling when hidden; /status 5s when not playing.

- [x] **P3. GET /system walks both caches every 30s.** (S)
  `_dir_size` os.walks a 20GB spotify cache (tens of thousands of syscalls,
  SD wakes) for a battery pill that needs none of it (sysinfo.py:294).
  Fix: 10-min TTL cache, refreshed by sweep/prune.

- [x] **P4. Battery tracker writes the SD every 60s on battery.** (S)
  sysinfo.py:273 — JSON write+rename per minute for a counter that
  tolerates staleness. Fix: persist every 5 min or on ≥1 % change.

- [x] **P5. /status re-parses library.json every second when idle.** (S)
  daemon.py:1073/1132 → `load_library()` full parse per poll in the box's
  most common state. Fix: mtime-cache in `load_library()` (copy the
  `_queue_map` pattern, daemon.py:144).

- [x] **P6. UI fetches remote cover art at the track-change instant.** (S)
  ui.py:1354/artwork_async — fires exactly when the CDN load + AVDTP are
  busiest. Fix: delay remote fetches ~3s or skip while `radio.busy()`.

- [x] **P7. Small trims.** (S) avahi `publish-workstation=no`;
  rtc-save timer 30min→6h; default screen_brightness 100→75
  (~10–20 mW screen-on). Governor cadence/iw mechanics reviewed: fine as-is.

## P3 — Boot

- [x] **B1. `_wifi_boot_reenable` runs before the HTTP server binds.** (S)
  daemon.py:2482 — three subprocess spawns with up-to-5s timeouts delay
  "listening", and the screen waits on /system. Fix: bind + log first, do
  wifi re-enable in a thread.

## P4 — Maintainability (code-quality lens)

player.main 382, do_POST 226, status 211). Env naming clean (88 TAPBOX_*
vars), no shell=True, no bare except. The `daemon.<name>` alias layer is a
test contract — every refactor must preserve those module-level names.

  31 sites across 10 files. `paths.write_json()` + opportunistic
  conversion. No monkeypatch risk. (S)
- [ ] **M2. Split `Orchestrator.status()`** into `_status_mpv` /
  `_status_spotify_pending` / `_status_ghost` (pure moves; keep calling

- [x] **M3. One `internet_up()`** — four copies (player.py:215,
  daemon.py:2039, daemon.py:2243 inline, content.py:82). The inline
  boot-resume copy bypasses the `_internet_up` test seam today. Keep the
  daemon alias. (S)
- [ ] **M4. One config.yml rewriter + one `restart_go()`** — four regex
  rewriters and seven scattered `systemctl … go-librespot` calls. Keep
  `daemon._retarget_go_librespot` / `_go_unit_active` names (patched 2×/8×).
  (M)
- [ ] **M5. Split `do_POST` (226 lines)** into playback/wifi/bt handlers +
  a `with quiesced():` context manager for the 6 repeated

- [x] **M6. Delete dead names** — daemon.py unused imports `hashlib`, `re`,

- [ ] **M7. player.main (382 lines):** reuse `library._sync_args_for`

- [ ] **M8. Helpers:** `spotify.volume_pct` (4 copies of steps-scaling),

- [ ] **M9. install.sh (850 lines):** move the six static systemd units to

## Suggested order of attack

1. **R3 + R4 + R7 + M6** — one short session, pure safety, no behavior change.
2. **R1 (rig verify) + P1–P5** — the power batch; ~30–60 min extra runtime.
3. **Q2 + Q1** — kill the live flake mechanism, resurrect the worst-bug e2e.
4. **R2 + M2 (+ B1)** — the lock/status surgery, one focused session.
5. **R5 + R6** — the two missing healers.
6. **M1/M3/M8 helpers** opportunistically; **M9/M10/Q3** when the mood strikes.

## Verdicts (one line each)

- Architect: sound architecture, unusually complete self-healing; the one
  systemic weakness is ORCH.lock doubling as state guard and operation mutex.
- RF/power: burst discipline is strong; what remains are unmanaged radio
  actors (bgscan, WAN probe, PWA polling) worth ~5–10 % of idle battery.
- Code quality: debt is concentrated (status/do_POST/player.main), not
  diffuse; ~100 copy-pasted lines collapse into three helpers.
- QA: field-bug coverage is unusually strong, but everything cross-process
  is untested and the worst bug's only repro was deleted.
